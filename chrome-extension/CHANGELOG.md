## `v1.7.1` (2026-11-04) — 🧹 修复兜底扫描把侧栏推荐用户记进名单

> 在真实账号上跑完 v1.7.0 的对账后发现的问题。`v1.7.0` 的 tag 保持不变。

**真实账号上跑对账后发现并修复的问题**
- 对账在真实账号上执行：粉丝移出 64 人、关注移出 77 人，被移出的人没有一个还留在名单里，资料全部保留。
- 但对账后库里仍是粉丝 2216 / 关注 2457，比主页 2,182 / 2,401 多 34 / 56。查明原因：**DOM 兜底扫描会把页面右侧栏「推荐关注」里的用户也记成名单成员**（它们和名单里的用户用的是同一种 `UserCell`，兜底扫描取的是整个文档）。证据：名单里没有 API 资料（`id` 为空）的粉丝恰好 35 人，其中与你有过互动的是 0 人、库里没有他们的任何推文；而有 API 资料的粉丝是 2181 人，与主页的 2,182 只差 1。
- 修复：兜底扫描只在 `[data-testid="primaryColumn"]` 主列内取用户卡片；找不到主列时宁可不扫。API 采集不受影响，所以兜底失效最多少一层冗余。
- 库里已经混入的这几十个账号不需要专门清理：下次「全量深采对账」时，它们不在 API 名单里，会被当作已不在名单里的人移出。
- 对账完成提示现在会写明「其中 N 人没有 API 资料」：这类人只可能来自页面兜底扫描，数量多说明有无关账号混入。第二次对账后库里仍有粉丝 32、关注 60 个这样的账号，都与你零互动，原因未查明，暂不自动移除。

## `v1.7.0` (2026-11-04) — 🔄 名单对账：取关的人不再留在库里

> 在 v1.6.1 之上新增，`v1.6.1` 的 tag 保持不变，方便回退。

**名单对账（新增）**

此前粉丝/关注名单只增不减：取关你的人、你取关的人会一直留在库里，库里的数字会比 X 主页上的真实数字大（实测库里 2228 / 2461，主页 2,182 / 2,401）。大屏上"🔄 全量深采对账"按钮的提示曾写着"适合每周查一次取关掉粉"，但代码里并没有删除逻辑，这个提示与实现不符。现在补上：
- **只有"全量深采"才会对账**，增量巡检仍然只补新、不删人。
- 全量深采翻粉丝页、关注页时，判断"到底了"不再看"库里有没有新增"（库里已有两千多人，翻页几乎全是已知面孔，会提前误判到底），而是看本轮累计看到的人数是否连续 12 轮不再增长。
- 到底后，用本轮扫到的名单替换库里的名单。**被移出的人不会被删除**，而是存进 `lists_removed`（记录移出时间），其用户资料和推文都保留；之后他再关注回来，会自动从 `lists_removed` 里拿掉。
- 保护闸，任何一道不过都不动库，并在完成提示里写明原因：没确认翻到底部；一个人都没看到；看到的人数不足库里人数的 70%；看到的人数不足主页显示总数的 90%（如果取得到）。
- **已知局限**：库里自己账号资料里的粉丝总数/关注总数目前是 0（X 接口字段位置可能已变，未深查），所以"对照主页显示总数"这一道闸目前不会生效，完成提示会注明"未能取得主页显示的总数，请自行核对"。请在对账后自己对一下主页上的数字。
- **对榜单的影响**：粉丝名单是榜一、榜二的硬门槛，取关的人对账后会从榜单里消失，榜单人数会变少。

## `v1.6.1` (2026-11-02) — 🛠️ 数据归属、点赞合并、写盘与巡检稳定性修复

> 一次代码审查后的修复版。**评分规则与 `config.json` 一个字没动**；会变的是「哪些人被认作你的粉丝」和「点赞者名单是否完整」，所以升级后榜单可能有少量变化（见下方「升级影响」）。

**会让榜单出错的问题**
- **名单只认「我自己的」关注/粉丝页**：此前打开 `x.com/任何人/followers`，页面上的人会被记成你的粉丝；同页的「推荐关注」等其他响应也会被一并打标。现在必须同时满足：页面主人是你、请求是 `Followers/Following/BlueVerifiedFollowers` 接口、页面类型与接口一致。判断以「请求发出时」的页面为准，响应回来前跳转页面也不会错配。DOM 兜底扫描同样受限。
- **`db.me` 不再被页面主人顶替**：原先 `me: me || owner`，`document_start` 阶段侧栏未渲染时，会把正在看的主页账号当成你。现在识别不到 me 时暂缓处理（最多约 8 秒），而不是猜一个。
- **聚合点赞通知更新后不再丢旧点赞者**（`merge-core.js`）：「A、B、C 赞了你」更新为「D、A 赞了你」时，此前整体替换导致 B、C 消失。现在同 schema 取并集（顺序稳定、重复喂入零变化）；schema 升级时仍整体采信结构化名单，用于纠正旧数据里混入的引用作者。

**写盘与性能**
- 开着 X 页面时，页面每 2.5 秒重发同样的头像/名单/me，后台每次都整库重写。现在页面侧只上报变化的内容，后台只在库内容真的变化时才写盘：有新数据立即写，头像/资料等次要变化合并后 5 秒慢写，重复点赞行（`collapsed`）与未变化的 me 不再触发写盘。
- 旧版 `localStorage` 数据的迁移改为「内容签名 + 后台确认」：成功后记标记，内容没变不再重复迁移；失败下次会重试。旧数据本身不删除。
- 大屏的 seed 基线改用库内 `seed_version`（按扩展版本）记录，每个版本只导入一次，取代原来「推文数 < 3000 或头像数 < 1450」的魔法数字判断。seed 的账号与库里的 `me` 不一致时不合并。seed 里的关注/粉丝名单只在对应名单为空时采用，避免把早已取关的人加回来。
- 补推文作者不再计入 `newItems`（它是修复旧行，不是新数据），否则会拖慢巡检的空转判定。

**巡检**
- 手动停止不再被当作「完成」：不再弹「已完成」、不再打开大屏，已采到的数据照常落盘。
- 修复「停止后立刻重新开始，旧循环从 sleep 醒来与新循环同时驱动同一个标签页」：每轮巡检带唯一代号，旧循环醒来即退出。
- 完成提示按模式显示「全量深采」或「增量巡检」，不再一律写「增量」。

**大屏与导出**
- 头像加载失败时露出首字母：原先的内联 `onerror` 会被扩展页 CSP 拦截，现改为事件捕获。
- 榜单表新增绿色「本周 +N」徽标（0 分不显示），此前 v1.6.0 的说明里有、但大屏并未实现，只有 Python 报告有。
- 表头与「互关 (+8)」等分值文案改为从 `config.json` 读取，改配置后界面同步变化。
- 圈圈图中心节点不再写死某个账号的昵称和头像；库里没有头像时用首字母渐变兜底。
- CSV 导出防公式注入：以 `= + - @` 开头的昵称/说明加 `'` 前缀；账号与主页链接格式不变。
- 导出文件后释放 Blob URL。

**公开发布前的收口**
- **seed 只在「同一账号」时合并**：此前库里 `me` 为空（全新安装）也会合并，别人装上会看到作者的粉丝、关注和推文，并且 `db.me` 被设成作者的账号。现在必须库里已识别出账号、且与 seed 里的账号完全一致才合并；`me` 为空时不合并也不记版本，等识别出账号后再判断。发布版不带 seed 文件时只记一次，不再每次打开大屏都产生一次 404。
- **去掉第三方头像服务 `unavatar.io`**：此前缺头像的账号会向该服务请求，等于把粉丝的账号名发给第三方，与「纯本地」不符。现在只用在 x.com 上采到的 `pbs.twimg.com` 头像，没有就显示首字母；manifest 里同步移除了 `unavatar.io` 主机权限。
- 账号未识别时，大屏顶部显示「未识别账号」，不再只剩一个 `@`。
- `cdp-collect.mjs` 不再写死 `E:/X-tools`，改为以脚本自身所在目录为根。
- 文档里的 `file:///E:/...` 链接改为相对链接，安装说明改为通用写法；根 README 增加「快速开始」。

**真实浏览器测试后的修复**（测试在真实 X 账号上执行，名单归属、账号识别、巡检、升级不丢数据均通过；以下是测试中发现的问题）
- **巡检接管错标签页**：原先取 `tabs.query` 返回的第一个 x.com 标签页，在 A 标签点巡检时实际被驱动的是 B 标签。现在按顺序选：发起巡检的标签页 → 当前窗口正在看的 x.com 标签页 → 任意 x.com 标签页 → 新建；正在写推文（`/compose`）的标签页不会被接管。
- **进度只发给被巡检的标签页**：其他 x.com 标签页的悬浮窗一直显示「⚡ 90s增量」，用户会以为没启动而反复点。现在进度与停止状态广播到所有 x.com 标签页，任何一个标签页都能看到进度、点停止。
- **没有 seed 文件时每次打开大屏都请求一次**：扩展包内文件不存在时 `fetch` 直接抛错而不是返回 404，原先的空 `catch` 让「已处理」永远记不上。现在只请求一次。
- **未回关表静默截断**：超过 300 人时只显示前 300 行且没有提示（测试中 361 人显示 300 行）。现在会写明总人数和未显示人数，并提示用搜索或导出 CSV 看全部。

**升级影响（请留意）**
- 之前被误记入你粉丝名单的账号不会自动清除（名单仍是只增的，对账功能尚未做）。如发现榜单里有不是你粉丝的人，需要在全量深采后人工核对。
- 老用户的库没有 `seed_version`，升级后首次打开大屏会补合并一次 seed（安全：账号一致才合并、已有资料/推文不被覆盖、点赞走幂等合并、名单非空则跳过），之后不再重复。
- 缺少头像的账号现在显示首字母，不再回退到 `unavatar.io`。想要头像，需要在 x.com 上浏览到该账号（插件会自动采集）。

**测试**：新增 `test_hook_ownership`（13）/ `test_hook_dedupe`（10）/ `test_background_save`（21）与对应 harness，另在 `test_likes_merge` 补 4 例，共 48 例；每组修复都已用旧代码对照验证过能失败：名单归属/me 回退/点赞并集 10 例在旧代码下全红；写盘与迁移去重 13 例在旧代码下失败；巡检生命周期 3 例（停止误开大屏、全量文案、旧循环复活）在旧代码下失败。其余是「有新数据仍立即落盘」之类的保护性对照用例，旧代码本来就通过。

之后又补了发布安全用例 `test_release_safety`（9 例，其中 4 例会真实启动 Chrome 加载扩展）与巡检选标签页用例 7 例，同样都用旧代码对照验证过。

**测试环境说明**（Windows）：
- 需设 `PYTHONUTF8=1`（`audit.py` 输出 `⚠` 时会因 gbk 报错）。
- 本机 anaconda 自带的 `pytest-remotedata` 与新版 pytest 不兼容，需加 `-p no:remotedata -p no:doctestplus -p no:openfiles`。
- 需 `pip install tzdata`：Windows 的 Python 没有系统时区库，不装会有 3 个时区相关用例失败。不装时全量为 276 通过 / 4 失败；装了之后第三方测试机报告剩 1 个失败（`test_not_followed_back::test_sample_order_keep_list_and_web_match`，期望 34.1 实得 33.8），这是上游 Xfan-audit 的问题，不涉及插件。

## `v1.6.0` (2026-11-01) — 📈 双时间轴：累计分 + 本周新增

> 解决「榜单只反映历史总贡献、看不到谁最近在升温」的问题。**累计分一个字没动。**

- **新列 `week_earned` / `week_visits`**：只统计**本周**（自然周，周一 00:00 起，UTC+8）发生的回应事件，**不含基础分**。
- **「现在」用数据里最晚的事件时间**，不取挂钟时间 —— 同一份数据任何时候重算，结果都一样。
- **累计分与档位完全不受影响**：用改动前的代码逐人对照，两榜 302 人分数 0 差异。
- **展示**：榜单页新增「本周升温 TOP 10」区块；卡片上加绿色「本周 +N」徽标（0 分不显示）。
- **配置**：`config.json` 加 `week_tz_offset_hours: 8`；顺带修掉 `_merge()` 只认三个键、导致该参数取不到值的问题。

**为什么不做滚动周榜**：当前数据只覆盖约两周，周榜与累计榜几乎重合（差 32 人、TOP5 相同）；等积累到三个月，滚动周榜会每周大换血，纯累计又会变成「老人榜」。两列并行更稳。

**测试**：新增 `tests/test_week_window.py` 7 例（周界前后、时区换算、累计分不变、空数据）；`test_scorer_parity` 扩到 11 例，新增本周两列的逐人比对。

## `v1.5.0` (2026-11-01) — 🔍 点赞链路无损化：合并去重、结构化提取、盲区回填

> 修的是「点赞数据越采越脏」这个根因，不是某个单点 bug。

- **合并层统一（新增 `merge-core.js`）**：通知 id 不稳定（同一事件换会话就换 id），线上 786 条里只有 496 个唯一事件、37% 是重复行。原来 background 与 dashboard 各写一份「按 id 整条替换」，导致 v10 抓到的正确行永远覆盖不了旧空行。现在三键索引（`id` / `时间+点赞者` / `时间+帖子`）任一命中即合并，字段级回填且绝不用空值覆盖非空。
- **计数语义拆分**：`added` 才计入巡检的 `newItems`，`upgraded` / `collapsed` 只触发落盘 —— 否则「补字段」会被当成「有新数据」，90 秒巡检跑满不切页。
- **提取层结构化**：`page-hook.js` 改为直接读 `template.from_users`，不再递归 `walk(template)`（那会把被赞帖作者和引用推文原作者扫成点赞者）。新记录带 `url` / `likers` / `schema:2`，可回溯。
- **去身份硬编码**：`console-collect.js` 的 `h !== "aigcgu"` 与 `cdp-collect.mjs` 的 6 处 URL + `me` 全部参数化（`--me` / `XFAN_ME` / `__FA_ME`）。注意：`cdp-collect.mjs` 现在**必须**传 `--me`。
- **参数单一来源**：新增 `chrome-extension/config.json`，大屏评分时传入；此前 JS 读代码常量、Python 读 `Xfan-audit/config.json`，改一边等于没改。
- **数据回填**：旧空行按「同时间+同点赞者」自动补 `tweet`，62 条补齐；786 → 486 条（折叠 300 条纯重复），`(人,帖)` 对 496 个一个没丢。
- **修一个隐蔽 bug**：合并时把 legacy 记录标成 `clean_v10`，会让下游跳过剥离启发式，把引用作者当成点赞者（实测多算 2 对）。现在只有「所有来源都可信」才标干净。

**测试**：新增 `test_likes_extract` / `test_likes_clean` / `test_likes_merge` / `test_likes_pipeline` 共 45 例，覆盖双份采集器对拍、v2 不剥尾、折叠计数、幂等、结构护栏（禁止内联第三份合并实现）。全量 208 例，仍只剩上游那 1 个历史失败。
