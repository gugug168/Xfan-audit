# ⚡ X-Fan 铁粉与回访审计器 (Chrome Extension `v1.8.1` · v10 双榜版)

> **零额外请求 · 纯本地无限容量存储 · 双榜独立计分 · 90 秒每日增量巡检 · 同心圆「铁粉圈圈图」与超清荣誉海报生成**

---

## 一、核心定位

`X-Fan 铁粉与回访审计器` 是一款运行在本地 Chrome 浏览器的 Manifest V3 扩展程序，专为 X (Twitter) 创作者打造，解决三大核心痛点：
1. **谁是「有来有往」的真朋友？（🎯 榜一：受邀回访榜）**：我去他帖子下互动后 **7 天内**，他是否真的点进我主页、在我原创主帖下评论或点赞？
2. **谁是「不请自来」的真爱粉？（🔥 榜二：自来水铁粉榜）**：我近期没触达过他，他却主动来到我原创主帖下评论、多轮交流或点赞？
3. **谁是「单向消耗」的白眼狼？（🧹 榜三：未回关清理清单）**：我关注了他甚至多次去他帖子下互动，他却始终不回关？

### 🔒 三条安全铁律（架构级强约束）
1. **零额外 API 请求**：插件只通过 `MAIN` world 被动读取你浏览器页面自身收到的 GraphQL 响应（`fetch` + `XHR`）与页面上已渲染的 DOM 头像，**绝不向 X 服务器伪造或发送任何额外接口请求**。
2. **零自动社交动作**：绝不自动点赞、绝不自动关注/取关、绝不自动发帖或私信。
3. **只认可见证据**：只统计有明确推文 ID 和时间戳的原创主帖评论、原创主帖下多轮对话、只赞我主帖的净点赞，彻底剔除转推/引用连带赞与自己给自己点赞。

| [content-bridge.js](content-bridge.js) | `x.com` 页面 `ISOLATED` World | 接收 `page-hook.js` 的增量数据包并转发给 `background.js`；在 X 页面右下角渲染可折叠悬浮胶囊（`⚡ X-Fan 铁粉审计`，版本号从 manifest 读取） |
| [background.js](background.js) | 后台 Service Worker | 维护 `chrome.storage.local` 中的 `xfan_db_v10` 本地全量库；调度 6 步巡检队列（`原创主帖` → `notifications` → `search(to:me)` → `with_replies` → `followers` → `following`），手动触发，非定时；v1.7.0 起「全量深采」会翻到底并做名单对账，取关的人移入可恢复列表，配 4 道保护闸 |
| [merge-core.js](merge-core.js) | 点赞合并规则 | 三键索引（id / 时间+点赞者 / 时间+帖子）去重与字段级合并；background 与 dashboard 共用同一份，禁止内联第二份 |
| [scorer.js](scorer.js) | 评分核心引擎 | 纯 JS 实现的 **v10 双榜评分引擎**，与 Python 版 `fan_json_to_data.py` + `return_visit.py` 100% 逐位对齐 |
| [dashboard.html](dashboard.html) | 独立审计大屏 UI | 五大 Tab 看板：🏆永久累计受邀回访榜、📅本周回访榜、🔥永久累计自来水铁粉榜、未回关白眼狼清理表、**🪐 铁粉圈圈图 & 荣誉海报生成器** |
| [dashboard.js](dashboard.js) | 大屏交互与绘图控制器 | 负责表格筛选、与海报勾选联动、在线文字/昵称编辑器、1600px 超清 **同心圆「铁粉圈圈图」+ 荣誉卡片** Canvas 渲染、CSV/JSON 导出与历史基线自动合并 |
| `seed-baseline.json`（**仅作者本人本地使用，不随公开仓库发布**） | 个人历史基线包 | 作者自己账号的历史快照。只有库里已识别出的账号与基线里的账号**完全一致**时才会合并；其他人安装时没有这个文件，也不会合并任何别人的数据 |

## 三、如何安装与更新

### 1. 首次安装
1. 打开 Chrome 地址栏输入 `chrome://extensions/`，开启右上角 **「开发者模式」**。
2. 点击左上角 **「加载已解压的扩展程序」**，选择本仓库里的 `chrome-extension` 文件夹。
3. 打开 `https://x.com` 并登录，**先访问一次你自己的主页**，插件会据此识别你的账号（悬浮窗右上角会显示 `@你的账号`）。识别出账号之前，大屏顶部会提示「未识别账号」，此时也不会开始巡检。
4. 数据只保存在你自己浏览器的本地存储里，不会上传到任何服务器，也不会请求第三方头像服务。

### 2. 日常代码更新后如何生效
由于你是以「已解压的扩展程序」直接挂载本地的 `chrome-extension` 目录：
- **只改了大屏 UI / 海报 / 算分逻辑（`dashboard.html`、`dashboard.js`、`scorer.js`）**：直接在已打开的插件大屏页面按 **`F5` 刷新** 即可秒级生效！
- **改了版本号或后台脚本（`manifest.json`、`background.js`、`page-hook.js`）**：在 `chrome://extensions/` 页面点一下本插件卡片右下角的 **🔄 刷新图标**，再刷新大屏即可。

## 四、核心功能使用指南

> **第一次上手请先看仓库根目录的 [README.md](../README.md)**：安装 → 识别账号 → 首次全量深采 → 每天增量，以及备份、常见问题都在那边。本节讲功能与实现细节。

1. **⚡ 90 秒每日增量巡检**：
   - 点击大屏右上角 **`⚡ 90秒每日增量巡检`**（或 X 页面右下角悬浮窗上的 `⚡ 90s增量`）。
   - 插件自动在一个 x.com 标签页里依次巡检 6 个页面：「原创主帖 → 点赞通知 → 别人回我 → 我发出的回复 → 新增粉丝 → 新增关注」，每个页面遇到本地已采集过的内容、连续数轮（粉丝/关注页 2 轮，其余 3 轮）无新增就切下一页，全部完成后自动刷新大屏。随时可点「停止巡检」，停止不会丢已采到的数据，也不会误开大屏。
   - 「90 秒」是大致耗时：实际约 1～4.5 分钟，取决于你的数据增量。
   - **增量只补新、不删人**；要清理已取关的人，请用下面的全量深采对账。
2. **🔄 全量深采对账（v1.7.0 起，唯一会修改真实名单的功能）**：
   - **入口只有大屏**的「🔄 全量深采对账」（`#btn-patrol-full`），X 页面悬浮窗上没有这个按钮。点下去会先弹确认框，写明会占用一个 X 标签页 3～6 分钟、会替换粉丝/关注名单、被移出的人可恢复、榜单人数会变。**跑之前先点「📤 导出备份 JSON」。**
   - 与增量的区别：粉丝页 / 关注页会一直翻到底 —— 不再看「库里有没有新增」，而是看本轮累计人数是否**连续 12 轮（约 24 秒）不再增长**（`RECONCILE_FLAT_ROUNDS = 12`）；增量模式是 3 轮、粉丝/关注页 2 轮。
   - 到底后 `applyReconcile()` 用本轮扫到的名单替换库里的名单。被移出的人**不删除**，写入 `db.lists_removed[kind][handle] = 移出时间`，其用户资料和推文都保留；之后重新出现（回关）会自动从这个列表里清掉。
   - **4 道保护闸**，任一不过就不动库，完成提示写明原因：① 没确认翻到底部 ② 一个人都没看到 ③ 看到的人数不足库里人数的 70% ④ 不足主页显示总数的 90%。拒绝时提示形如 `⚠ 粉丝名单未对账（<原因>），库里的名单没有改动`。
   - **已知局限**：库里自己账号资料的粉丝/关注总数目前取不到（为 0），第 4 道闸**实际不生效**，完成提示会注明「（未能取得主页显示的总数，请自行核对）」。请对完账自己打开主页核一下数字。
   - 成功提示形如 `✓ 粉丝名单已对账：现有 N 人，移出 N 人，新增 N 人，其中 N 人没有 API 资料（可能是页面推荐的无关账号）`。「没有 API 资料」的账号来自页面兜底扫描（v1.7.1 起兜底扫描只在 `[data-testid="primaryColumn"]` 主列内取用户卡片，不再把侧栏「推荐关注」算进名单），这类账号不影响榜单排名。
   - **对账后榜一/榜二人数变少是预期**：粉丝是双榜硬门槛，取关的人不再进榜。
3. **🎯 榜一（受邀回访榜）& 🔥 榜二（自来水铁粉榜）**：
   - 支持按 `全部 / S档 / A档 / B档 / C档` 筛选、关键词搜索、一键导出 CSV。
   - **「主页到访 / 翻阅深度」列**精确区分：
     - `✓ 翻阅主页 (N篇/跨M天)`：互动过你 ≥2 篇不同原创帖（铁证翻阅过主页时间线）
     - `✓ 进主页回帖 (1篇)`：在你去外部串门后点进你主页评论了 1 篇原创帖
     - `- 仅外部串接话`：只在别人的推文串里顺嘴接话（0 篇你的原创帖）
   - 每行第 2 列自带 **`上海报` 复选框**，随手打勾即可加入海报。
4. **🧹 未回关清理清单（Tab 3）**：列出你关注了但没回关你的人，按「我回过他的次数」排序。**超过 300 人时只渲染前 300 行**，页面会写明总人数和未显示人数，用搜索框或「📊 导出当前表 CSV」查看全部（v1.6.1 起不再静默截断）。
5. **🪐 铁粉同心圆「圈圈图」& 荣誉海报生成器（Tab 4）**：
   - **0. 画面样式**：支持一键切换 **`🪐 同心圆「铁粉圈圈图」+ 荣誉卡片（推荐爆款）`**、**`⭕ 纯享同心圆「铁粉圈圈图」（大方图）`**、**`📋 经典双列荣誉榜卡片`**。
   - **1. 出图榜单**：支持单独发 **`🎯 认真回访榜`**、单独发 **`🔥 自来水真爱榜`** 或 **`🏆 双榜合体全貌图`**。
   - **2. 档位范围 & 3. 前几名**：支持 `只选 S 档`、`S+A 档`、`S+A+B 档`、`全部档位`，以及 `前 5/8/10/12/16/20/30 名` 或自定义任意前 N 名。
   - **自定义选人与改字**：支持点 **`⬜ 清空重选（我点谁谁上海报）`** 手动挑人，支持实时修改主标题、副标题、签名栏以及每位铁粉的显示昵称和卡片文案，下方圈圈图、卡片与配套 `@` 发推文案实时同步重绘！

## 五、备份、迁移与卸载

| 动作 | 位置 | 说明 |
|---|---|---|
| 导出备份 | 大屏「📤 导出备份 JSON」（`#btn-export-json`） | 下载 `fan-audit-YYYY-MM-DD.json`，含名单、用户资料、推文、点赞记录 |
| 导入 / 迁移 | 大屏「📥 导入合并 JSON」（`#file-import`） | 走 `XFAN_IMPORT_JSON` → `mergeBatch(payload, true)`，**是合并语义**：把备份并回当前库，**不会覆盖或清空现有数据**，也不是「一键回滚到备份那一刻」 |
| 换 Chrome 配置 / 换电脑 | — | 数据存在当前 Chrome 用户配置的 `chrome.storage.local` 里，不跟着账号走；靠上面两个按钮迁移 |
| 更新版本 | 见第 3 节 | 覆盖文件夹 + `chrome://extensions/` 点 🔄 刷新，**不丢数据** |
| ⚠️ 卸载 | `chrome://extensions/` 点「移除」 | **会删掉扩展保存的全部数据**，卸载前务必先导出备份 JSON |

## 六、常见问题速查

| 现象 | 处理 |
|---|---|
| 悬浮窗不显示 `@账号` / 大屏写「未识别账号」 | 在 x.com 打开一次自己的主页并等几秒。识别不到 me 时插件会暂缓处理（最多约 8 秒），不会把当前页面主人猜成你 |
| 刚装完大屏是空的 | 正常。发布版不含 `seed-baseline.json`，一定是空库；先跑一次全量深采对账建立基线 |
| 库里粉丝/关注数比主页大 | 名单原本只增不减；跑全量深采对账。对完自己核对主页数字（第 4 道保护闸目前不生效） |
| 头像不显示 | 头像加载失败时显示首字母（v1.6.1 起走事件捕获，不再用会被 CSP 拦的内联 `onerror`）；只采 `pbs.twimg.com` 头像，不请求任何第三方头像服务 |
| 点了巡检好像没反应 | 进度会**广播到所有 x.com 标签页**（v1.6.1 修复）；接管顺序为「发起巡检的标签 → 当前窗口激活的 x.com 标签 → 任意 x.com 标签 → 新建」，`/compose` 标签不会被接管 |
| 巡检/对账卡住 | 网络慢或 X 限流；对账会拒绝执行并写明原因，库不变。可点「⏹ 停止巡检」，已采数据照常落盘 |
| 升级后功能没变 | 改了 `manifest.json` / `background.js` / `page-hook.js` 需在 `chrome://extensions/` 点 🔄 刷新；只改大屏文件时大屏按 F5 |
| 打开大屏控制台有 404 | 旧版无 `seed-baseline.json` 时每次开大屏都会 `fetch` 一次；v1.6.1 起按 `seed_version` 每版本只请求一次，发布版不再反复 404 |

更多面向新用户的分步说明见仓库根目录 [README.md](../README.md)。
